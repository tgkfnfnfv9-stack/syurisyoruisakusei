# 共通Google Driveの初回設定

このバックエンドを保存先アカウントでWebアプリとして公開すると、誰が見積もり・報告書を操作しても、データは公開者のGoogle Driveへ保存されます。

## 公開手順

1. 保存先にするGoogleアカウントで [Google Apps Script](https://script.google.com/) を開きます。
2. 「新しいプロジェクト」を押します。
3. プロジェクト名を `小林機械 書類データ共通バックエンド` にします。
4. 最初からある `Code.gs` の内容をすべて削除し、このフォルダの `Code.gs` を貼り付けて保存します。
5. 右上の「デプロイ」→「新しいデプロイ」を押します。
6. 種類は「ウェブアプリ」を選択します。
7. 「次のユーザーとして実行」は `自分` を選択します。
8. 「アクセスできるユーザー」は `全員` を選択します。
9. 「デプロイ」を押し、公開者のGoogle Driveへのアクセスを許可します。
10. 発行された `/exec` で終わるウェブアプリURLをコピーします。

## 共通PIN

`ad5d1bc7`

PINはWebアプリ側とGitHub Pages側の両方に同じ値を設定します。

## 次の作業

発行されたウェブアプリURLをアプリの `google-drive.js` に設定し、共通Drive方式を有効化します。

## 公開済みバックエンドの更新

GitHubの更新だけでは、公開済みウェブアプリに新しい `Code.gs` は反映されません。

1. 保存先Googleアカウントで、現在のウェブアプリを公開したApps Scriptプロジェクトを開きます。
2. `Code.gs` の内容をこのフォルダの最新版で置き換え、保存します。
3. 「デプロイ」→「デプロイを管理」を開きます。
4. アプリで使用しているウェブアプリの編集ボタンを押します。
5. バージョンを「新バージョン」にして「デプロイ」を押します。
6. 「次のユーザーとして実行: 自分」「アクセスできるユーザー: 全員」を確認します。
7. 見積書・報告書ページで共通Driveへの接続、保存済みデータの読み込み、入力後の保存状態を確認します。

既存デプロイを更新すれば、アプリに設定した `/exec` URLを維持できます。新しいデプロイを作ってURLが変わった場合は、`google-drive.js` の接続先も更新してください。

## 旧見積書データと競合防止

- 保存先は「小林機械 書類データ」内の「見積もり」「報告書」です。
- 見積書は旧「見積書」フォルダも検索します。同じ番号・件名の書類が現在の「見積もり」フォルダにもある場合は、現在のフォルダを優先します。
- 旧フォルダの書類を読み込んで保存すると、更新番号の一致を確認したうえで、同じファイルIDのまま「見積もり」へ移動して更新します。
- 別の端末で変更された書類や、更新番号を持たない古いデータからの上書きは拒否します。端末内の必要な変更をJSONで控え、最新版を読み込んでから編集してください。
- 共通PINは共通保存先への接続確認に使います。利用者個人のGoogleアカウントを認証する仕組みではありません。
